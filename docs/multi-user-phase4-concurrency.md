# 多用户阶段四：并发采集与资源独占

基于阶段三 `2525715ae4ea2465dde41dcb0f34177bb2d5b547`。这是隔离候选实现，未部署。阶段三的额度、单用户一个未完成任务和取消/发布裁决保持有效；本文件取代阶段三文档中“不同用户执行仍串行”的阶段性说明。

## 调度与锁

required 模式使用持久准入队列。worker 从较早任务开始寻找可执行任务；忙碌账号不会阻塞后面的其他账号任务。不增加同一用户内部的新任务队列。

- 每任务独立执行锁：控制库同级 `<db-stem>.task-locks/<task-hash>.lock`。获得新文件描述符上的锁才能恢复旧任务，不能仅凭心跳超时回收。
- 每采集账号独占：`CRAWLER_BROWSER_PROFILE_ROOT/.resource-locks/<resource-hash>.lock`。抖音按账号 ID 隔离，底层 CloakBrowser Profile 锁继续生效。采集、轮换、交互登录、修改及删除账号使用同一资源锁。
- worker 先取任务锁、系统容量、已授权账号锁，再启动任务。运行时重查用户有效期及实际执行账号授权。账号删除/修改遇占用返回 409；登录遇占用不启动浏览器。
- 爬虫子进程继承任务、容量和账号锁 FD。关闭父进程 FD 不主动解锁；孤儿子进程尚在时仍阻止重复派发、提前释放名额和资源复用。禁止删除锁文件强制解锁。
- 原冻结配置与实际执行账号分别记录；自动轮换只在当前用户授权范围内选择，并遵守相同账号锁和原有冷却规则。初始分配账号保守地占用到本任务返回；轮换时临时持有其他账号，可能降低利用率但不会抢占其他任务。
- 单独恢复分析/报告或核对已完成采集结果时，不因采集账号忙碌或冷却而等待新的采集资源。发布结果恢复仍先验证正式报告。
- 非抖音适配器仍使用共享浏览器资源锁，暂不承诺其独立账号并行。disabled 旧模式继续保留采集目录全局锁。

等待原因持久保存于 `task_admissions.waiting_reason`：`system_capacity`、`account_busy`、`no_available_authorized_account`；最后一项包括失效或冷却后暂无可用账号。`resource_account_id` 记录分配账号。额度接口的 active_task 携带这些字段；完整中文页面提示属于阶段五。

## 运行配置

| 配置 | 候选默认 | 含义 |
| --- | --- | --- |
| `TASK_WORKER_PROCESSES` | 2 | worker 管理进程维持的独立工作进程数；CLI `--workers` 可覆盖。 |
| `TASK_EXECUTION_CAPACITY` | 2 | 同一运行环境同时执行的任务上限，覆盖采集、分析及报告阶段。 |
| `TASK_ANALYSIS_CAPACITY` | 2 | 同时进行的帖子分析组或报告生成组上限，不等于所有内部供应商 HTTP 请求的精确并发数。 |
| `TASK_RESOURCE_LOCK_DIR` | `<data-dir>/resource-locks` | 执行与分析容量槽的稳定目录。 |

启动：`python -m backend.investigation_creation.worker --workers 2`。`--once` 只尝试一个任务，便于受控验证。管理进程补位意外退出的 worker；收到 SIGINT/SIGTERM 后停止接单，等待在途任务结束。服务管理器强杀仍依靠继承 FD 防止错误恢复。信号处理函数只设置标记，不在信号内获取 multiprocessing 锁。

API、全部 worker 必须使用相同控制库、数据目录、输出目录、Profile 根目录、资源锁目录和容量配置。`REQUEST_SCHEDULER_DB` 在这些 worker 间共享，原有平台请求间隔、并发及冷却保持生效；不能每任务创建限速库。同一平台请求可按频率串行放行，而两个浏览器任务仍交叠执行。

该方案限同一主机的本地文件系统，不提供多主机调度或网络盘租约。默认 2 是候选验证值，不是生产容量保证。分析组内部并行仍受原分析器自身配置约束，生产资源和供应商额度需另行测量。

## 验证与边界

`tests/test_task_concurrency.py` 覆盖独立子进程实际交叠、取消 A 不影响 B、活跃任务不被过期心跳抢占、孤儿进程保留自身资源、账号忙碌排队、容量等待、撤销授权、登录/维护冲突、分析等待取消、无需采集的恢复，以及真实 worker 管理进程补位与进程组退出。测试报告适配器覆盖发布及额度结算，不能替代真实模型验收。

2026-09-20 本地真实探针使用两个新应用用户，各自仅授权一个不同的抖音账号，以及两个完整 Profile 的隔离副本。固定 Chromium 145.0.7632.109.2，关键词搜索第 0 页，流式模式，每账号一条，关闭评论、媒体和自动分析。两个独立 worker 的采集执行重叠约 13.08 秒，各落一条 task_contents，任务所有者及执行账号匹配，交叉访问返回 404。共享请求限速日志确认仍在协调请求。

本探针没有生成真实报告。采集后清理仍在等待分析的任务，确认执行和账号锁释放后返还名额。不要将“采集成功”记作“成功报告计次”。真实模型报告链路及云端容量仍属于后续完整验收。

初次探针错误地关闭流式模式，触发爬虫基线的非流式最少一页行为，在 180 秒保护时限取消，分别留下 12/13 条数据；保留失败探针收据，不将它作为一条任务通过依据。恢复发布版流式配置后，一条任务验证通过。非流式最少一页是既有行为，本阶段不改变爬虫源码。

原始黄金 Profile 在探针前后逐文件摘要一致。测试不修改或重启旧正式服务、腾讯云服务及原 Profile。候选账号副本和认证材料仍在私有运行目录，不纳入 Git 或公开日志。

## 升级及回退

增量增加 `task_admissions.waiting_reason`、`resource_account_id`；初始化在写事务内检查并迁移字段，避免多个进程同时启动重复加列。已有账本、所有者和额度不重置。

从阶段三切换前停止接单、结束旧 worker 和旧爬虫子进程，取得一致性数据备份，再统一切换 API/worker。阶段三全局锁与阶段四任务锁不能混用。保留数据库、Profile、密钥、输出及共享限速库；禁止覆盖云端业务库。

回退前同样停止新接单并排空阶段四任务。禁止新旧 worker 并行驱动同一目录，禁止删除锁、重置账本或退到无鉴权模式继续对普通用户开放。需要强制中断时，先证明对应执行停止，再使用有鉴权的恢复流程核对报告和名额。
