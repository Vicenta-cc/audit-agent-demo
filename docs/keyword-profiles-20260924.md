# 可选关键词主题指导

关键词仍统一通过 `create_lexicon_edit` 生成会话编辑稿。新增可选的
`generation_request.keyword_profile`，由协调 Agent 根据用户完整调查目标选择：

| 值 | 用途 |
| --- | --- |
| `sexual_service_leadgen` | 色情服务引流候选检索 |
| `gambling_financial_abuse` | 网络赌博、金融黑产和电诈助诈候选检索 |
| 省略或 `null` | 不加载主题模板，按原通用要求自主生成 |

没有匹配模板不报错、不硬套类别；明确传入未知名称仍是参数错误。
普通招聘、电脑性能跑分等不能仅因词面命中而套用风险主题。

## 组装与权限边界

- 模板及版本位于 `backend/resource_management/keyword_profiles.py`。
- 只在词库工具的 schema 中提供该参数，规则生成 schema 不变。
- 主题模板不替换原通用召回质量要求；生成 Schema 统一由专用编写器选择。
  后续结构修复将新词库生成改为 `GeneratedLexicon`，详见 `lexicon-authoring-20260924.md`；
  不是每份主题模板维护一套 Schema。
- 在专用生成请求的 user JSON `requirements` 中，按“主题模板指导 / 用户本次要求”分区组合。
  模板不是用户原话；用户限定的调查对象、平台、范围、数量优先，不扩大目标。
- 模板为空时不追加任何主题指导；相同生成 Schema 版本下，provider messages 与通用路径相同。
- `exact_terms` 原文词表请求不注入任何主题示例，原词及顺序校验不变。
- 生成仍只建立会话编辑稿；保存、采用、启动仍分别需要原授权。
- 已有完整 `content` 导入不调用生成模型，也不添加模板。
- 不新增分类调用、自动重试、供应商分流或主 system prompt 段落。

## 追溯

生成工具回执的 `generation_profile` 包含 requested_profile、applied_profile、profile_version
和 skip_reason；该回执沿用现有工具执行记录持久化及幂等重放。
生成日志记录实际采用的模板/版本及请求哈希。元数据不进入词库内容与 content_hash，
后续 `get_resource_edit` 不保证携带最初生成回执的元数据。
修改模板内容时递增版本，不把模型输出视为已证实的术语含义。

## 验收

`tests/test_keyword_profiles.py` 覆盖可选参数、未知名称、规则隔离、原 Prompt 保留、
原词保护、模板元数据、导入不生成、保存/回读、工具重放和拦截不重复执行。
真实模型验收应给自然语言目标，不手填模板参数，核对工具选择、实际加载版本、
生成结构与内容；至少包括风险主题以及含歧义词的普通主题。
模板选择正确不代表词条真实性、低噪声或供应商永不拦截。

### 本轮结果

- 相关自动化回归：254 passed（含资源生命周期、引用采用、原提示约束保留）。
- 真实测试：隔离数据库运行完整 Hermes 创建 Agent；协调和专用生成均使用统一 Qwen 入口，
  不手工填写模板参数。四个场景，每个最多四次 provider 请求，共十六次。
- 色情服务引流：选择正确，但专用生成返回 `RESOURCE_GENERATION_INVALID`，没有编辑稿。
  Agent 随后再次尝试生成；测试请求上限阻止后续网络调用，最终回合失败。
  不能将上限触发造成的连接错误当成供应商内容拦截，也不能宣称本例完整通过。
- 网络赌博：选择合并模板，生成七词，真实编辑稿与最终回复均成功。
- 金融助诈：选择合并模板，生成六词，真实编辑稿与最终回复均成功。
- 电脑性能跑分：选择 `null`，生成六个硬件测评词，未硬套助诈模板，完整回合成功。
- 没有正式保存、创建草案、启动采集或重启现有服务。

本轮只证明这四次请求的模板选择符合预期，不证明任意主题均能正确分类，
也不证明生成候选的真实流通性或噪声水平。生成备注仍可能出现无依据的确定性表述。
色情场景的具体结构错误尚未从该次记录解析出，不能猜测为某一个字段；
失败后 Agent 再次尝试也应作为独立的恢复行为问题继续追踪，而非本次新增重试逻辑。
以上为模板首轮验收结论。后续原请求重放与生成结构修复记录见 `lexicon-authoring-20260924.md`。
