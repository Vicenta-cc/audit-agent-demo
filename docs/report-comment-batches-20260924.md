# 全部评论：每轮最多 100 条纯文本交付

## 语义与范围

仅新增统一报告问答启用，旧报告工具不变。没有恢复评论 Drawer、增加卡片或新的前端接口。

- 普通“看看评论”：原 list_post_comments 少量预览，默认 5 条，单次最多 20 条；原风险筛选、账号引用和模型解释保留。
- 明确“全部逐条列出 / 展示所有原文”：同一工具传 batch_action=start，按当前帖及筛选结果准备前 100 条，不再同轮翻完所有页。
- 用户下一轮说“继续”：batch_action=continue，服务端从成功交付检查点续读。300 条对应 1–100、101–200、201–300 三轮。
- 风险筛选在分页前执行；风险、无风险、未知、全部各自保存进度。变更范围必须重新开始，不能沿用另一筛选的进度。
- 同一回合只允许一个批次。重复同范围调用重放同批；换范围或借普通分页继续读取会被拒绝。普通预览不建立全部交付检查点。

替换了原“全部匹配评论时沿所有分页读完”的一句冲突提示；细节在原工具 Schema/说明内，没有再追加另一份 system prompt。

## 为什么不让模型复述 100 条

分批工具向模型返回总数、本批起止序号和剩余数，不把 100 条原文再送入模型让它复写。
原文由服务端以普通聊天编号列表生成；作者与评论均做 Markdown/HTML 文本转义，且沿用公开回答内部引用脱敏。
模型成功回合的最终公开回答保留模型对其他问题的回答，再追加服务端原文列表（见后文边界收尾）；原生 transcript 保持真实模型输出，不伪造工具或模型消息。
批次不是“模型已经分析全部评论”的凭据。需要分析内容时仍需读取证据，不得把工具计数当阅读完成。

普通回答流式机制不变。批次原文在最终交付时通过现有 answer_delta / answer_reset 机制同步；不是模型逐字生成 100 条，也不额外调用模型逐条复写。

## 检查点、失败与权限

使用原有带完整性校验、会话及授权快照绑定的 reference_states 存储批次和分页游标。
仅在公共回答 complete_turn 成功之后确认进度；模型拒绝、回合失败、中断不推进。
完成回答后、写进度前若崩溃，下轮根据已持久化的回合终态补确认；同回合恢复重放原批次。
重启可恢复；其他会话不能使用其帖子引用；强制重建引用代次或授权/快照变化不会恢复旧进度。
本次没有改变授权范围、正式报告数据、采集或审核流程。

## 续读失败归因纠正与工具加载门禁

后续检查发现，`tool_call` 是 Hermes 原生延迟工具入口；之前成功的持久化 transcript 也使用它，内部 name 为 list_post_comments。不能把 Unknown tool 日志单独归因于模型编造工具名。

独立续读测试的命令漏设工作目录，使用了默认旧目录。保持解释器、代码导入路径、会话、Hermes home 和配置相同，仅改变 cwd，离线构造检查结果为：

- 默认旧目录：agent.tools 与 valid_tool_names 都为空。
- 当前候选工作树：tool_search / tool_describe / tool_call 三个合法入口正常加载。

因此这次续读失败的直接原因是测试启动错误：Hermes 项目插件发现依赖工作目录。没有证据支持给模型输出增加包装解码补丁。本次没有改写工具调用、增加重试或修改 system prompt。

最小防护：新增统一报告 Agent 创建时检查。模型可见 schema 与 valid_tool_names 必须一致具备业务入口，并核对 scoped 原始业务目录；延迟入口还核对实际可调用范围。缺失时关闭 Agent，在任何推理前停止。服务端以 report_tools_unavailable / environment_preflight_failed 返回明确的环境错误，非自动重试，不再归为未知结果或让模型空跑纠错。检查只针对统一报告模式，未改创建 Agent 或旧报告模式。

### 收窄后的实现

- 复合问题不再被列表覆盖：保留已校验的模型回答，再以“评论原文”小标题追加确定性的 Markdown 列表。列表和其他回答共用原公开流式最终同步机制；未新增 Drawer、卡片或前端 API。
- 已确认进度作为每轮临时服务端事实提供，只含最近最多五个筛选范围的批次元数据，不含评论正文、不持久化为重复历史。不是追加一大份静态 system prompt。准备但未交付的批次不进入该事实。
- 新增 `read_comment_delivery`：无参数返回最近十个已交付批次；明确批次引用和展示编号后，仅读取那一条原文、作者引用与审核状态，可继续调用账号工具。不能默认猜测“最新”、跨筛选复用编号、读取未交付/其他会话/失效引用。旧批次可凭明确引用定位。

- 匹配评论者统计由服务端按稳定账号身份计算，范围为该帖全部匹配评论，不是本批人数；缺失身份单独计数，同昵称不合并。
- 保留成功落盘后才确认进度、失败不推进、重启恢复及授权快照绑定。供应商最终回复失败仍不会被当成已交付；这次没有移除模型最终成功这一依赖。
