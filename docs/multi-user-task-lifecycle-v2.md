# 多用户候选：接受任务计次与整任务结束

2026-09-20，基于阶段四 `e814526aaa7e7fefa0cefe72a37ba3e63a78c711`。本文件替代阶段三文档中的额度与终态恢复规则；阶段二身份、七天有效期、数据授权和阶段四资源隔离继续保留。候选代码尚未部署。

## 确定规则

| 操作或结果 | 处理 |
| --- | --- |
| 新建对话、讨论、待确认草案、已有报告问答 | 不扣 |
| 确认执行并成功持久接受，包括排队 | 按北京时间接受日期扣一次，每用户每天三次，全部对话合计 |
| 重复请求、同任务分页、自动重试、暂停/继续采集或分析 | 不再扣；跨天继续也不再扣 |
| 报告成功 | 不再次扣 |
| 用户结束整个任务，包括排队时结束 | 不退款；停止前仍占未完成任务位置 |
| 采集已经或可能开始，之后失败 | 不退款；确认停止并到终态后释放用户位置 |
| 系统故障，可靠记录证明完全未开始采集，任务终止且执行停止 | 仅退款一次，归原扣次日期 |
| 暂停或结果未知 | 保留未完成位置，不能直接删除 |
| 任务已明确结束且执行已停止 | 可删除会话，不要求必须有报告；删除不删额度账本 |

同一用户仍最多一个未完成任务。每个对话沿用既有一条调查流水线；新调查在新对话确认。本次没有新增“重试报告”页面功能。accepted_v2 终态任务不能通过隐藏的旧恢复接口重新启动。

## 账本与可靠性

新增列采用增量迁移：旧行默认 `quota_policy=report_v1`、`charge_state=LEGACY`、`collection_phase=UNKNOWN`，保留旧收据语义，不重算或清空历史。新接受记录为 `accepted_v2/CHARGED/NOT_STARTED`。从历史已结束任务重新准入的兼容路径保守标记 UNKNOWN，不能推断其从未采集。

`state=RESERVED` 只代表未完成位置；`SUCCEEDED` 是正式报告发布完成；`RELEASED` 是无报告终态，**不表示退款**。是否退款独立读取 charge_state。旧 report_v1 当天仍按其原规则兼容统计；额度接口返回 legacy_record_count，页面明确提示存在旧记录。

准入仍在同一个控制库 `BEGIN IMMEDIATE` 事务内完成额度检查、扣次、唯一用户位置、冻结参数和持久派发记录；调查 Run 也在该事务中创建。Job 和报告由 worker 通过稳定标识在各自存储中完成，不需要跨进程内存入队。

启动爬虫前先写 `MAY_HAVE_STARTED`。只有第一次 Popen 同步抛出 OSError、明确没有创建子进程时，才撤回启动标记并记录系统故障；Job 物化失败及爬虫准备文件目录时的 I/O 故障也记录系统故障。后者不撤销既往启动标记。既往已启动、旧记录 UNKNOWN、子进程启动后报错/无结果/超时，都不能据此自动退款。系统在启动标记落库后崩溃，保守保留收费；需管理员取得额外证据后处理，本次没有增加人工退款入口。

退款需要：accepted_v2、CHARGED、NOT_STARTED、明确 system_failure、无 end_requested_at，且调用方取得停止证明。取消与退款并发时读取事务内最新记录，用户明确结束不退。使用新 FD 获得阶段四任务锁才证明旧 worker/继承 FD 的爬虫子进程停止；仅超过心跳时间不释放位置。

取消请求持久写入 end_requested_at，返回不释放位置。恢复进程确认停止后终止 Run/Job、禁用旧恢复/发布入口并释放位置。报告发布已进入受保护的提交阶段时不强行取消，由原发布裁决完成，防止“结束成功”与报告成功同时出现。

- 侧栏和监控页显示今日已用/剩余次数及北京时间重置提示；接受任务后刷新，页面定期重新读取，失败时不显示旧额度为当前值。
- 暂停任务提交结束后继续轮询，直到后台确认终态；额度不足/已有未完成任务的 409 不再误报成“配置版本变化”。
- 按用户最新确认，所有新增按钮和对话框复用现有组件与样式，样式文件没有改动，不重新设计页面布局。
- 待分析使用 queued_analysis_count；兼容旧数据时从 pending 减去 failed，失败数单列。
- 已有部分成功、部分失败生成报告的证据门槛不变；全部失败无报告也允许终态。无报告终态删除前确认没有排队/分析中的残余工作。
- 删除会话获取任务锁并在数据库事务内核对终态及未完成记录。保护 task_admissions、task_admission_commands，不随业务记录删除。暂停不能直接删除。
