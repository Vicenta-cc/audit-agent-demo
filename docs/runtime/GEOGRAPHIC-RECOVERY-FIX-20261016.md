## 原因与处理

1. 地域详情下载交给异步审核后，审核仍持有采集线路的借用。下一次采集过早申请同一线路，会与本任务自己的借用冲突。现在先等待借用释放，再申请下一次线路；等待期间检查执行权、分析异常、暂停和停止。
2. 长任务可能超过出口观测的有效期。下一次采集前，对已授权、已持有租约的账号走现有出口刷新流程，再检查可用性。账号锁、出口一致性、风险暂停和授权检查继续生效。
3. 外层任务可恢复，不代表内层地域执行状态能安全重试。仅在进入线路上下文时、爬虫尚未调用前发生的 `PROXY_BUSY` / `SUPPLEMENT_DEFERRED` 会记录为可延期状态。详情延期保留预算预留、顺序和审计记录，不重复交付已完成内容。
4. 本地调查的恢复请求改由持久化命令交给 worker，继续使用原 Run 的确认配置、执行权和校验。重复请求不重复执行；恢复排队后到来的停止指令优先。分析恢复不会再次清除晚到的停止标记。
5. 恢复资格读取持久化地域快照并验证任务绑定，不依赖可能滞后的页面投影。无法确认外部调用结果的失败仍需核对；页面明确显示“采集记录待核对”，不误报成账号登录问题。

## 兼容边界

- 不把旧的普通 `CollectionRouteError` 自动改判为“爬虫未启动”。旧任务缺少证明时不能直接重试。
- 不重置候选筛选、已确认地域、已完成审核、采集预算或风险保护。
- 不通过忽略失败的地域检索词来强行生成报告。
- 中断且调用结果不明的恢复命令不自动重放，避免重复外部操作。
