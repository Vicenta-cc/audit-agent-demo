# 地域筛选改造计划

修订日期为 2026 年 11 月 19 日。按用户最新决定，首版采用纯后台地域筛选，先在本地测试；风险预筛 AI 保留。本版同时包含克拉玛依四区映射、作者资料重试与跨轮复用、增量存储及生产版本基线。本次按已确认生产基线在独立 worktree 本地实施；生产部署及历史任务重跑不在本次范围。实施与验证记录见同目录 GEOGRAPHIC-MENTION-VALIDATION-20261119.md。

## 一、目标与适用范围

将地域相关性改为按地名提及、评论文字和作者 IP 分档判断，在原有风险预筛结果上增加独立地域标签。

- 原风险预筛选的代码和逻辑均不得改动。地域筛选作为外层增量功能接入，只读取现有风险输出；身份排除、规则命中、模型判断、分数、标签、异常处理和同分排序全部保留。
- 启用地域筛选的任务采用三档地域优先级，并支持每个搜索词最多三轮候选筛选。
- 普通预筛任务沿用逐词单轮流程。
- 创建任务时，可选目标继续限定为省级地域、地级市。帖子中的地点识别可以覆盖地区、自治州和新疆县级地名。
- 全国保留省级、地级基础覆盖。新疆增加全部县级正式名称及精选简称、区域表达。
- 首版地域识别仅采用后台地名及别名匹配、归属映射和作者 IP，按固定规则生成档位；不调用地域 AI，不设置 AI 补漏或兜底，不建立自动学习别名流程。先通过本地测试评估覆盖情况，再依据实际漏判决定后续是否引入地域 AI。

## 二、地域标签和双标签排序

### 三档地域定义

| 档位 | 条件 | 目标为克拉玛依时的例子 |
|---|---|---|
| 第一档，目标地域直接命中 | 标题或正文提及目标地域、认可的别名，或确认隶属目标地域的地点 | 克拉玛依、克拉玛依市、克拉玛依地区、独山子区、独山子、乌尔禾区、乌尔禾 |
| 第二档，同省文字线索 | 第一档未命中，标题、正文或已采集评论中，出现目标所属省份或确认归属该省的地点、区域表达 | 新疆、北疆、伊犁、喀什。仅评论提及克拉玛依或其下属区及认可简称也归此档 |
| 第三档，作者 IP 同省 | 前两档未命中，作品或作者资料中的作者 IP 属地对应目标所属省份 | 作者 IP 属地为新疆 |
| 未命中 | 三档均没有可确认依据 | 无相关地名，作者 IP 缺失或属于其他省份 |

目标为新疆省级地域时，标题、正文提及新疆或新疆下属地点进入第一档，仅评论提供新疆相关地点进入第二档，仅作者 IP 为新疆进入第三档。其他省市采用相同的三档规则，匹配其各自目标和所属省份。

执行以下规则。

- 任意一个有效命中即可提供对应档位，采用最高档位。
- 人物来源、店名、否定句、多地比较中的有效地名都计入提及。
- 评论仅使用归属于当前帖子的已采集评论文字，不使用评论者 IP。
- 作者 IP 优先采用当前作品返回的作者 IP 属地，缺失时采用已关联作者资料中的 IP 属地，并保留具体来源。空值和无法解析的值不提供第三档依据。
- 按用户可选择的省级、地级目标归一化匹配结果。同一市内的市区同名或多个下属地点不作额外消歧，统一提供该市及所属省份的依据。仅当候选实际跨越不同目标城市时检查归属冲突；只能确认共同省份时，仅提供省级依据。
- 匹配和消歧不根据任务目标强行选择某个同名地点。

### 双标签排序

先执行原风险预筛及去重资格检查，再进行地域选择。

1. 从有入选资格的候选中，选择最高可用地域档。
2. 同档内直接使用现有 `rank_candidates` 排序。
3. 按任务冻结的每词选取量选取，当前默认场景为每词 1 条。
4. 地域档位不折算为风险加分。第一档弱风险候选可以排在第三档强风险候选前，风险标签和分数仍保留各自原值。
5. 第三档适用同一套原风险预筛资格，不额外继承旧地域规则中的“评论 IP 达标且必须强风险”条件。

### 原风险预筛代码与逻辑保护边界

- 以实施前确认的生产版本为基线，先列出风险预筛实现、调用接口和相关配置的保护范围。本次不重构、搬迁或改写原风险函数，不为地域筛选修改其输入输出协议。
- 原风险模型、提示词、输入构造、规则、阈值、身份判断、评分、标签、入选资格、重试与异常处理以及 `rank_candidates` 均保持原实现。不得把地域词、档位或目标省市注入风险提示词或计算。
- 在地域专用外层流程中调用现有风险接口，读取完整的候选风险结果；地域证据和档位存入独立记录，通过帖子标识关联，不修改或覆盖原风险结果对象。
- 原风险排序实现不变。外层按既定地域档位筛选合格候选，同档沿用原风险排序及同分顺序；地域优先导致的最终选取差异属于新增地域规则，不能反向修改风险得分或原排序函数。
- 三轮补筛由地域外层负责调度，对每一新增批次照常调用原风险预筛；每批内部规则不变。普通任务不进入新增地域流程，仍按原单轮方式执行。
- 不因地域命中而复活被原风险规则排除的帖子，也不因地域未命中而跳过本应执行的风险流程。模型结果复用、去重与错误处理按原机制执行。
- 若现有接口无法取得所需风险结果，先记录具体接口限制并调整外层接入方案；不得借地域改造之名修改风险实现。任何确实需要改变此保护边界的工作须单独说明，不能混入本次实施。

## 三、地名资料与匹配实现

### 统一实体和别名

以行政编码关联标准地点，建立独立的内容匹配索引。全国基础目录提供省级、地级地点，旧地点表中的县级和景点条目继续按原归属接入。

同一地点的名称与别名按实体合并、去重并保留来源。更新行政记录时，已有别名需要显式保留或记录变更原因。修复“伊犁、伊犁州”在替换旧记录时丢失的问题。

### 新疆补充内容

- 加入所采用行政目录中新疆全部县级正式名称，包括县、自治县、县级市、市辖区及省直辖县级市。当前本机快照有 112 条县级记录，该数量仅作为该快照的校验依据。
- 接入明确的省级和地级归属。省直辖县级市直接关联新疆，不编造上级地级市。
- 首批地州简称包括伊犁、伊犁州、昌吉州、博州、巴州、克州、阿克苏、喀什、和田、塔城、阿勒泰。
- 首批县市简称包括库尔勒、库车、伊宁、博乐、莎车、泽普、叶城、巴楚、特克斯、昭苏、布尔津、富蕴、新源、沙湾、额敏、奇台、玛纳斯、石河子、阿拉尔、霍尔果斯、塔什库尔干、塔县。
- 克拉玛依四个区的正式名称和简称按下表完整纳入首批内容匹配索引。
- 首批区域表达包括南疆、北疆、东疆、南北疆、天山南北、全疆、疆内，统一提供新疆省级归属，不推定具体城市。
- 新疆书写变体首批包括 `Xinjiang`、`Xin Jiang`、`新 疆`、`新·疆`、`新彊`。英文匹配忽略大小写并检查单词边界。
- 单字“新、疆”及“XJ、自治区、兵团、西域”等高歧义表达不作为独立命中词。县级简称只采用明确列入补充表的条目，不批量去后缀生成。例如“温泉县”的正式名称可以纳入，“温泉”不自动成为新疆命中词。

| 独山子区 | 650202 | 独山子 | 克拉玛依市 | 650200 | 新疆维吾尔自治区 |
| 白碱滩区 | 650204 | 白碱滩 | 克拉玛依市 | 650200 | 新疆维吾尔自治区 |

这四组映射进入可执行匹配数据。标题或正文出现“独山子租房”“白碱滩生活”“乌尔禾旅游”等表达时，能够通过简称和行政归属命中克拉玛依市第一档。仅在评论出现时，命中第二档。

用户只能选择克拉玛依市，不能选择克拉玛依区。因此内容中的“克拉玛依”“克拉玛依市”“克拉玛依区”统一映射为可筛选目标克拉玛依市，并关联新疆；不增加判断简称究竟指市还是区的分支，也不为此调用 AI 消歧。四区行政编码仅用于底层归属与来源追溯，不要求筛选流程为“克拉玛依”维护两个候选身份。各区记录不会新增创建任务时的可选目标类型。

### 原文证据与名称冲突

匹配须保留原文字段、原文片段、位置、地点实体和归属。评论证据同时保留评论 ID。相互包含且实体相同的命中合并，明确的较长外地名称不能被内部重叠的新疆简称覆盖。全国县级资料可用于检查名称冲突，但正向县级召回扩展限定为新疆及已有地点条目。

“伊犁”“伊犁州”作为同一标准地点的别名归一化；“伊犁州”内包含的“伊犁”不重复计算。不同原文位置可以保留各自证据，但同一帖子不因别名数量、同市下属地数量重复入选或增加地域权重。

### 首版纯后台地域判断与本地试验范围

首版新策略的地域提取、归属及分档均由后台完成，缺少命中时也不触发地域模型。人物来源、否定句、店名等语境不否决认可地名的提及。没有可核验映射的表达不猜测归属，有其他有效文字或作者 IP 依据时仍按其分档。

风险预筛 AI 及其调用规则保持原状。旧地域 AI 模块仅按旧任务冻结策略继续使用，不删除旧任务所需依赖；新策略用独立版本分派，无需为本次试验新增 AI 模式切换系统。未来是否增加地域 AI 是本地效果评估后的独立决定，不自动启用。

## 四、逐词补筛、接口与兼容

### 参数和执行顺序

沿用现有候选量及每词选取量配置。已核对生产基线的候选量默认 10，实际候选批量为候选配置与每词选取量的较大值。每词选取量来自任务参数，调查参数默认 1。[当前参数计算](/Users/ext.wanghongtao6/Documents/Codex/development/geographic-mention-20261119/app/backend/investigation_creation/scope_search_plan.py:538)。

新增服务端地域任务参数 `geographic_max_rounds`（环境变量 `GEOGRAPHIC_MAX_ROUNDS`），默认 3，允许 1—3，确认时纳入任务冻结快照。确认预览显示实际轮数，首版不新增用户调节控件。

对每个搜索词顺序执行。

1. 取得一批候选，批量使用冻结配置，典型值为 10。
2. 执行原风险预筛，生成地域标签，排除重复、已审核及原规则不允许入选的帖子。
3. 在最高可用地域档内按原风险排序选取。存在可入选结果，即结束该词的补筛，继续原详情采集和审核流程。
4. 本轮没有任何可入选结果，才取下一批候选。
5. 达到三轮、数据源正常耗尽或任务总量上限后，结束当前词，按原执行顺序处理下一个词。

配置为每轮 10 条时，一个搜索词最多对 30 条不同帖子进行预筛。若每词选取量配置大于 1，选取最高可用档内最多相应数量。有结果但不足配置数量时，不为补满而增加轮次。

### 连续取数和断点恢复

- 扩展地域采集调用的续取信息，保存搜索会话、分页位置、页内未消费候选及已处理帖子 ID。
- 抖音接口每页请求 15 条，需要保留未消费条目，保证应用层每批 10 条连续取数。
- 轮次、候选批次、风险结果、地域结果和选取结果分别持久化。原有单批捕获记录的不可变约束继续成立，下一轮追加新的批次记录。
- 同词跨轮候选去重，任务内跨词只在最终入选时去重。同一帖子在不同关键词下仍按各词原始输入执行风险评估，不能仅按帖子 ID 复用风险结果。已保存的同批评估结果在恢复时复用；作者资料可在同任务同账号下跨词复用。重复结果和原有翻页停滞保护共同防止无限取数。
- 网络、登录、风控、解析或存储错误沿用异常处理，不能记成“地域无命中”后直接降档或跳词。
- 选取之后的下载失败、详情失败和预算结算沿用原流程。补筛轮次仅因预筛没有可入选结果而推进。

### 作者资料重试与跨轮复用

保留现有爬虫请求层的有限重试，在新地域流程中补齐跨轮复用；应用层不另套一层“缺少 IP 就重试”。该机制针对抖音，不能推定其他平台也具有相同接口行为。

- 保留当前准确触发条件：作者主页 GET 请求返回 HTTP 200、正文为 0 字节、类型为 application/json 且无 Retry-After，使用受管理的绑定账号和出口时，等待 10 秒后重试一次。仍为空则按现有失败处理。首次请求加这次重试最多两次；这不是所有网络错误的通用重试策略。
- 正常返回资料但没有 IP，与接口获取失败分别记录。前者不因缺少 IP 重试；后者保留失败原因和尝试状态。第三档没有依据时，不影响已成立的第一档或第二档。
- 普通作者资料补充失败沿用现有可选补充语义，不能伪造为“作者 IP 在外省”。限流、账号验证、登录失效、路由异常和取消信号继续按原机制传播，不因地域补筛而吞掉。
- 在同一次任务执行的同一平台、作者及有效采集授权范围内，跨词、跨轮复用作者资料获取结果和已消耗的重试次数。新进程或断点恢复不应自动重置预算；新任务不永久复用旧任务的失败结果。
- 优先接入现有执行记录和采集会话，保存紧凑的获取状态、尝试次数、来源及证据引用；不引入独立通用重试服务。作者资料结果供多个帖子引用，作品自身的作者 IP 仍保留作品来源，不把某条作品的 IP 覆盖成所有作品的共同事实。
- 通过现有事务与执行权检查记录请求尝试和完成状态。进程在请求后、结果落库前中断时，标记状态不确定，恢复时不无条件重发；具体恢复动作沿用采集恢复机制并计入剩余预算。
- 不为了已有文字命中而跳过原风险预筛依赖的作者资料请求：粉丝量、简介等身份字段仍按现有规则采集。

生产基线爬虫用实例内的空字典同时缓存普通获取失败和空资料；本地新策略已增加任务/账号绑定的持久记录，区分原因、保存预算并跨轮共享。单次重试没有必要在本次改造中替换成多次指数退避；如后续有并发重试拥塞证据，再单独评估。有限重试和避免多层重试的原则参考 [Microsoft 官方瞬态故障指南](https://learn.microsoft.com/en-us/azure/architecture/best-practices/transient-faults)。

### 增量存储与内存约束

App 业务状态沿用已修复的地域增量存储。采集子进程不能访问 App 私有数据库，因此仅为搜索续取与作者缓存使用 child UID 拥有的任务级 SQLite 侧车；它不保存 App 风险决策或另建业务状态机。

- 三轮候选、评论证据、地域标签和作者获取状态写入新增或变化的记录，历史批次保持不可变。共享地名目录及重复证据通过现有内容寻址记录复用，避免为每条候选复制整份目录或资料。
- 在线执行、恢复和页面轮询使用 `read_state()` 及紧凑摘要，按需要读取证据。`load()` 完整导出仅用于诊断，不进入每轮筛选或页面轮询路径；禁止对完整任务状态反复深拷贝、序列化和写回。
- 保留操作 ID 幂等、载荷冲突检测、历史完整性校验、执行权检查以及旧任务迁移与重放能力。新增批次和尝试记录使用稳定的操作标识。
