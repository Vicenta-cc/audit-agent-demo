# 会话与报告删除 · 2026-09-11

入口仍为 <http://127.0.0.1:3198/investigation>。在会话右侧“更多操作 → 删除会话”中确认“永久删除”。取消不改数据；删除中禁用重复提交；失败显示原因并保留会话；删除最后一个会话后显示新建入口。

## 删除范围

- 支持 A/B/C 历史会话、M3 创建会话和未生成报告的空白会话。
- 删除当前会话的消息、轮次、问答记录、工具记录、资料与查询结果、临时资源编辑、草稿及运行关联，以及对应报告的全部版本、正文、投影、报告冻结证据副本和生成检查点。
- 同一报告的内部问答会话一起删除；删除对应 Hermes 会话目录及问答缓存。跨报告查询不再加载已删版本。
- 历史导入保留不含正文的删除标识，避免重新启动时从归档自动导入；会话存储中的报告删除标识阻止持有过期报告上下文的并发请求重新创建会话。
- 此功能清除工作台的报告与会话数据，不清除独立备份、用于恢复的原始历史归档、原采集任务的审核数据与媒体、已正式保存的规则或词库，也不改其他运行环境。工作台没有撤销删除或回收站；恢复只能按运行备份说明操作。

## 执行保护

`DELETE /api/investigation-workspaces/{id}` 和 `DELETE /api/historical-report-workspaces/{id}` 成功返回 204；重复删除同一已删会话返回 204。不存在或无访问权限返回 404。排队、采集审核、报告生成、问答执行中返回 409，待结束后重试；被其他会话引用的草稿/运行也暂不允许删除。

删除在附加数据库写事务中重新核对所有权及执行状态，阻止 worker 同时领取目标运行。报告仅在本次写事务内临时解除删除触发器，提交前恢复原触发器；普通修改及删除仍受原不可变约束保护。业务事务失败回滚；派生缓存允许重新建立。SQLite 检查点库使用 WAL，本实现不承诺跨库断电原子性；发生硬件故障时按一致备份恢复。

前端环境检查和启动脚本按尚存报告验证健康状态，主动删除历史报告不再导致工作台无法进入或服务无法重启。
