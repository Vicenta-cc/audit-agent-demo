## 仅复核原任务失败帖子

原任务已发布部分报告，不允许通过普通恢复接口重新打开成功任务。维修复核使用独立数据库副本与输出目录，保留旧报告和成功帖子；不关闭身份检查，不改原任务的入场状态。

```bash
bash scripts/local-audit-runtime.sh run scripts/reaudit_failed_posts.py \
  --source-db /absolute/path/to/data/audit_index.sqlite3 \
  --source-output /absolute/path/to/data/outputs/SOURCE_JOB \
  --source-job SOURCE_JOB \
  --expected-failed 20 \
  --output /absolute/path/to/empty-reaudit-directory
```

此脚本复用真实 `AuditPipeline`，执行图片/视频、Dolphin、评论与融合的完整帖子审核。使用冻结规则/Prompt 和已采集评论，不重新采集。原数据库只读备份；结果只写副本。
`run` 同样先执行真实预检，并固定工作目录后再启动脚本；不依赖调用者的 shell 环境。
`manifest.json` 记录输入选择和规则快照，`summary.json` 持续记录进度；全部阶段日志在副本 `audit_index.sqlite3`，诊断在副本 outputs 下。
完成复核不等于原发布报告已更新，也不等于已通过报告问答验收；需要明确区分。
