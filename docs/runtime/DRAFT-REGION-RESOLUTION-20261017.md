# 草案省市组合地域识别（2026-10-17）

## 修改范围

基于 `0822832`，仅在 `scope_intent.resolve_region` 的原有精确名称/别名解析后，增加省市组合解析。不修改模型提示、对话历史、草案复制、地域预筛、行政区名录或账号/线路保护。

本次仅离线测试，使用隔离数据库与脚本化工具调用。不请求真实模型，不采集，不重启 3499 后台，不改线上。已有旧草案不会被批量重写，正在运行的后台不会因提交自动加载新解析器。

## 解析规则

- 单独的标准名称和别名保持原有优先级。例如“克拉玛依”仍是克拉玛依市，“吉林”仍待选择吉林省或吉林市。
- 组合输入必须完整拆成名录内的省级名称/别名和下级名称/别名；下级记录的省份代码必须与前缀一致。遍历所有合法拆分后按行政实体去重，只有唯一受支持实体才能直接解析。
- “新疆克拉玛依市”“新疆维吾尔自治区克拉玛依”直接解析为克拉玛依市；“浙江省杭州市”“浙江杭州”“浙江省杭州”“浙江杭州市”均解析为杭州市。
- 不删后缀、不做模糊匹配、不截取字符串后忽略剩余内容、不让模型猜测行政归属。
- “浙江克拉玛依市”提示省市归属冲突；“吉林”存在歧义；未知名称、多个地域、区县、街道及原先未支持的行政类型继续待确认。不会自动扩大成省级或全国范围。

## 保留的保护

名录完整性校验、用户原话来源、会话与用户归属、版本检查、原子更新、界面选择优先、显式清除、确认预览和执行能力检查均保持原逻辑。更新标题或资源时不会重新要求确认已解析地域；无法解析的新要求不会偷偷清除此前范围，待确认状态仍阻止启动。
