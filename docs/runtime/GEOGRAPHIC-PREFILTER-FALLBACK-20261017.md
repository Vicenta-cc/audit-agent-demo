# 地域预筛格式纠错与待判定兜底

## 范围

只修改地域预筛响应边界、纠错记录和待判定展示。草案地名解析、用户确认流程和已确认地域不变。不修改 MediaCrawler、固定 P3 源码、风险打分、账号与线路保护、预算、排序或报告完整性规则。

本轮只使用隔离数据库和模拟模型/爬虫做离线测试；不启动真实调查，不调用外部模型，不重启 3499 对应服务，不部署线上。提交不代表当前进程已加载修复。

## 处理顺序

1. 原协议可以接受的名称继续交给固定 P3 判断。
2. 模型输出省市组合名时，只有该组合逐字存在于同一字段原文、省与市都来自该字段候选、城市归属省一致、行政实体唯一时，才绑定到该城市候选。比如原文确有“新疆克拉玛依市”，可以绑定“克拉玛依市”。不按调查目标补地名、不跨字段、不做模糊匹配；暂不扩展到未知的多级区县组合。
3. 保存模型原响应、名称绑定依据、处理版本和固定 P3 结果，校验时确定性重放。旧版无处理版本的记录仍按旧协议重放。
4. 格式校验失败后，下轮请求携带上一轮原响应、具体错误和同字段候选白名单，总调用预算最多三次。
5. 调用前先持久化次数；进程丢失时，已开始但未落结果的调用计入预算，不冒充成功，也不因重启清零。已落完整结果而未写最终评价时，直接重放已存结果。
6. 耗尽后保存该条为技术性待判定，继续其他候选与检索词的预筛。为保持原有检索词、风险排序和地域档位优先规则，未完成的检索词不会被后续词越过进行正式选取。报告保持未完成，不能把该条算作外地、无地名或无风险。

合法的 `insufficient_context` 仍是已经完成的语义判断，与响应格式不合法区分。网络、授权、执行权或证据损坏等异常不通过此兜底自动放行。

## 持久化与后续处理

每条候选的 `geo_attempts` 是追加且不可清零的历史，最终评价必须与它一致；已完成的风险和地域结果不重复请求。耗尽记录提供独立待判定数量、错误及候选标识，页面显示“地域预筛待判定”，阻止普通恢复无限重复调用。暂不提供修改历史记录或人工放行功能；后续如需重新判定，应设计显式、审计且有界的处理入口。

旧任务已被标成 `failed` 的记录不会自动改判或恢复。详情变化后的地域复核仍使用严格校验；本次没有新增详情复核失败的自动恢复流程。
