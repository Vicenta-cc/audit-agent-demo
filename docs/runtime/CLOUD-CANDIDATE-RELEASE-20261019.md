## 目标与边界

交付一个版本固定、参数可核对、账号登录可用、完成多轮业务测试且有可演练回退路径的云端版本。先部署独立候选环境，通过验收再安排正式切换。旧生产在候选验收期间继续服务。

不把本地测试配置直接复制到云端，不把端口或 health 200 当作完整验收，不关闭鉴权、账号安全、执行权、出口或报告完整性保护。保留现有 systemd / 反向代理拓扑；生产前端交付构建产物，不暴露 Vite 开发服务。[依据：docs/runtime/UNIFIED-RUNTIME.md:18–22、100–108；deploy/camoufox/README.md:5–10、34–48]

2. 建立参数表：**当前生产实际值 / 代码默认 / 本地测试覆盖 / 候选值 / 生效来源与理由**。同时检查 runtime manifest、受控环境、系统设置数据库、已确认任务快照和用户本轮草案。API、worker、资源生成及报告问答进程的最终配置必须一致。
   历史分析记录链接还依赖 `INVESTIGATION_MULTI_ROUND_ENABLED` 及旧会话轮次成员数据；核对 workspace 是否返回指定旧 Run 的 `rounds`，保留缺失与无权限时的拒绝，不自动退查其他端点。

## 第二步：先证明可回退，再部署候选

1. 只读记录当前生产的准确 SHA、前端产物、服务定义、代理上游、受限配置引用、数据及 Profile 路径、共享 ASR 等依赖和磁盘余量。回退目标是当前正常生产版本，不是历史无鉴权版本。
2. 在一致停写/关闭 Profile 的窗口制作完整备份：业务、认证、账号、调度等 SQLite 及其一致内容，输出媒体、报告/Hermes 状态、账号加密 Key、配置和完整浏览器身份目录。通过 SQLite backup 与完整性检查，不只拷贝主 .sqlite 文件遗漏 WAL；实际在隔离目录恢复并核对账号归属、报告与媒体。
3. 区分两个回退时点：
   - **候选验收期间/正式开放写入之前：**旧环境未改动，可撤销候选或把入口恢复到已验证的旧上游。
   - **新版已接收业务之后：**必须证明旧代码可使用保留的新业务数据，或有已演练、可审计的数据兼容/逆迁移方案。账号引擎与 Profile 迁移也在此范围。不能恢复旧数据库而丢掉新任务或账号。
4. 在隔离副本上完成“旧版 → 新版写入 → 受控回退”演练，检查用户、任务、报告、账号安全状态与媒体引用。新旧 worker 不能同时写同一库或占用同一账号 Profile。

**完成条件：**恢复演练通过，明确回退命令、所需时间和数据兼容范围。若新引擎无法回到旧状态，不能把“保留旧目录”称为完整回退；先解决并复核，未完成不切正式流量。不得临时自动切回旧采集引擎。[依据：deploy/camoufox/README.md:86–113；MediaCrawler 交接:158–175]

## 第三步：云端独立候选环境与账号专项

1. 准备独立源码、venv、Linux 浏览器资产、systemd 单元、端口、数据库、outputs、Hermes、Profile、锁、调度及测试账号。采用受限 HTTPS 测试入口；保留登录认证，明确 WebSocket Origin 和代理 Upgrade 转发。候选不能消费正式任务或与旧环境并发操作同一平台账号；资源不足则使用独立测试主机。优先使用专属测试账号和独立物理出口，不能因分开调度库而绕开同出口的实际容量/安全限制；无法隔离出口时安排受控采集窗口，证明正式采集已排空后测试，不能让两套独立调度器互不知情地争用同一路线。
2. 候选在正式进程权限边界运行：专用非 root 浏览器身份、私有 Xvfb、Linux 匹配资产、固定浏览器版本与三份指纹模型资产、正确 UID/目录权限/进程退出与锁释放。父进程配置与浏览器子进程较小白名单分开，业务数据库不向浏览器开放。
3. 现有 `deploy/camoufox/README.md:3、52–84` 仍标注 G0 安全审查未关闭。先核对匹配这次资产的实际审查与预检收据；缺项就补证据，不能把模板或 `passed:true` 当验收结果。README 提及 G1–G10，但目前没有找到逐项完整定义；执行前必须把编号展开成下表的具名门槛，补齐对应命令、负责人、收据路径和通过标准，不能仅写“G1–G10 已通过”。短业务任务不能替代长时间/容量测试。
4. 候选保持隔离，完成真实迁移和基础健康记录后，通过维护工具受审收据受控解除候选维护，并重启候选 API/worker 验证准入；随后才进行扫码和采集验收。维护配置不热生效，不能为测试解除旧生产保护。登录专项：管理员及普通用户授权；新账号扫码、取消、超时、重新登录；平台身份一致；登录后采集复用；真实超过出口 TTL 后自动检查；断开再连与服务重启；账号登录/采集互斥；真实出口变化和风险暂停仍拦截；代理容量满提示准确。二维码/平台验证码由账号持有人操作。

**完成条件：**至少 5 个完整任务有报告及问答证据，覆盖地域 2 次、全国 2 次、主页 1 次；正式参数、权限、重启和跨报告测试通过；阻断问题为零。第三步具名门槛及长稳收据另行齐备。[依据：docs/runtime/UNIFIED-RUNTIME.md:127；docs/runtime/GEOGRAPHIC-MEDIA-HANDOFF-20261017.md:31–47、68–75]

## 第五步：正式切换与观察

1. 提交最终验收结果、参数表、资产清单与回退演练记录，列明全部缺口。形成具体可审核的切换方案后再进入切换窗口；本计划本身不等于已经执行切换。
2. 暂停新任务准入，排空采集、审核与登录进程；证明旧进程已退出，做最终一致性备份并把正式数据迁入新环境。候选测试数据不覆盖正式数据；验证与预演之间的新生产记录必须补齐。
3. 以实际正式用户/权限完成迁移后检查，再定向更换本域名上游或经核对的 manifest；Nginx 校验后 reload。保持共享 ASR 与其他站点原样，确认 App/Crawler SHA、dist 和 API/worker 配置摘要与验收版本一致。
4. 切换后立即验证登录、旧报告与媒体、账号状态、新建小任务、报告和问询；分批恢复准入，并观察至少 24 小时的任务/登录失败、模型/ASR/CDN 耗时、资源锁、队列和磁盘。
5. 触发回退：认证/越权异常、数据缺失、持续登录失败、执行权或线路异常、报告无法完成等。先停新准入并保全记录，再按第二步已演练方案回退；禁止恢复旧库覆盖切换后的新业务。旧 release、配置、备份和 Profile 归档至少保留 7 天，清理另行处理。

## 最终交付与停止条件

交付：固定发布版本、参数差异表、Linux 安装/启动与登录操作说明、至少三轮实测报告、可执行回退手册及演练结果、正式切换收据和观察记录。

任何源码/参数未锁定、资产审查缺失、生产鉴权或账号保护不通过、备份不可恢复、切换后写入不可兼容回退、真实完整链失败，都阻止切换；继续在候选修复和验证，旧生产保留。
