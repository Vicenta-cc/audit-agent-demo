# 默认单条演示与可选批量扩展

## 默认交付

一套前端、一套后端、一个 worker、一个持久化数据目录。初始化导入按报告范围裁剪的 Report A/B 及其公开问答证据；用户可查看、问答，也可登录自己的采集账号，新建最多抓取和审核1帖的任务，生成新报告并继续问答。

一个数据目录内部保留业务、对话、任务等 SQLite 文件；不是强行合并数据库。不需要额外的测试数据库或正式批量数据库。账号和模型密钥由使用者自行配置。

验收单条任务时核对采集与审核上限均为1，不能只限制审核数量。现有 demo 默认每帖最多300条评论、不抓次级；调整评论数量是另一个独立配置，不改变帖子数上限。

## 批量作为可选部署

现在提供 [民族 K 任务可执行安装与启动说明](ETHNIC_TASK.md)、`demo/ethnic.env.example` 和 `scripts/demo.py init-ethnic`。下文保留通用批量配置原理；民族任务优先按该专门说明操作。

后续需要批量时可在停止执行、确认队列状态后，以明确配置提升上限；若必须同时保留单条演示与批量后台，再部署两套后端/worker与独立数据目录，使用持久化路由共用前台。

参考配置：17词、每词最多20帖、总计最多340帖、每帖最多1000一级评论、采集并发1、不抓次级评论、任务内按内容ID去重。这是有限批次，不是无限运行或保证24小时。

默认启动器 `scripts/demo.py` 读取 `.env.demo.local`；批量配置可另建 `.env.batch.local`，使用独立 `DEMO_DATA_DIR` 和端口。参考增量如下：

```dotenv
DEMO_DATA_DIR=./data/batch
DEMO_API_PORT=8168
DEMO_WEB_PORT=3168
M3_POSTS_PER_KEYWORD=20
M3_ANALYZE_LIMIT=340
M3_COMMENTS_PER_POST=1000
CRAWLER_MAX_CONCURRENCY=1
```

新建的 V4 规则草稿会按以上配置生成确认预览，并把数量和规则冻结到任务快照。确认前必须在界面检查每词上限、总研判上限和评论数；本例只有确实使用 17 个词时总上限才是 340。已有任务不会随环境变量更改。旧 V3 兼容协议仍固定 1 条，不要手改已有任务 JSON。

```bash
cp .env.demo.local .env.batch.local
# 修改为上述独立目录、端口及批量参数，并配置独立可用账号。
.venv/bin/python scripts/demo.py init --config .env.batch.local
.venv/bin/python scripts/demo.py start --config .env.batch.local
```

这会启动一个独立批量环境和前端地址，不会自动把它接到单条演示前台。默认只交付单环境启动器；如果要求两种环境实时共用一个前台，需要另行部署并验证任务路由网关。不要让两个环境同时使用同一平台账号。


旧 `scripts/collection_trial.py` 是本机 launchd 双环境启动脚本，带开发机约束，不能作为跨机器批量安装命令。若复用，先迁移路径、账号选择、运行角色注入与身份检查；任务参数以最终保存快照为准。本文提供架构和配置说明，不附带自动启动正式批次的任务或后台定时器。

批量需要持久化失败计数、可停止 worker、进度和结果核验。单次模型超时最多一次补试；整轮故障排查修复后最多重启一次，之后失败停止。遇验证码/人工验证立即记录并停止。不得把进程无限自动重启当作可靠性方案。

## 单条会不会使用新版 Prompt 和思考模式

采集数量与审核配置独立。核对 backend/rulesets/trial_profiles.py 和 Pipeline 的任务快照读取逻辑后，当前行为如下：

| 使用情形 | 实际行为 |
| --- | --- |
| 单条新任务选择 `ruleset.ethnic-content-review.k-trial.v1` 的发布修订 | 与批量 K 使用同一套固定审核模板；评论 thinking=true/max_tokens=6000，融合 thinking=true/max_tokens=3000，均为 qwen3.7-plus、120秒超时 |
| 单条新任务选择其他已有 RuleSet | 使用其自身编译结果；不自动换成 K |
| 用户现场生成新的普通 RuleSet 或临时规则 | 走普通编译；不会自动继承 K 的特制模板和思考配置 |
| 原有任务/报告 | 保留当时冻结配置与结果，不因代码里新增 K 自动重审 |
| Report A/B 或新报告的对话问答 | 属于独立问答流程，不由评论/融合的思考参数控制 |

因此，想在单条演示中验证 K，需先在该环境执行 `scripts/demo.py init-ethnic --config <该环境配置文件>` 登记 K 资源，并在新任务中选中其发布版本。仅修改 max_notes=1 不会关闭思考；仅安装最新代码也不会让所有 RuleSet 自动开启思考。

若产品要求“用户生成的任何规则也默认开启思考”，需要单独设计通用审核配置，并验证新规则的编译和执行快照；目前没有这个全局默认承诺。不要把民族 K 专属业务指令硬塞给其他主题。

共享 Pipeline 的协议修复与 K 特制模板也要区分：证据引用校验、评论结果保留、超时补试等代码可能影响多个任务，不是都由 K ID 开关控制。发布时以固定提交和相关回归测试为准。
