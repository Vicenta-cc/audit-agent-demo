## 修改范围

- 新报告只向模型暴露 `view_post_comments`，必填 `display_mode=preview|browse_all` 和 `risk_filter=all|risk|no_risk|unknown`。
- preview 复用原有权限校验、冻结评论、账号引用及游标，缺省 limit=5，仍允许显式 1–20 条。browse_all 不接受 limit/cursor，创建完整匹配列表，不把原文塞进模型。
- 回执增加局部交付状态：预览已准备好，或入口已创建、需要用户点击；纯展示要求简短确认，有额外分析需求仍可按需读取材料。不根据关键词正则猜测或覆写用户意图。
- 入口的内部 view_id 不再返回给模型，仍持久化并由原授权回合 API 提供给前端。避免模型将 ID 拼成伪链接；不改变列表权限或生命周期。
- 旧 `list_post_comments` / `open_post_comments` handler 保留兼容历史调用，旧报告工具目录不变。更新公开活动名称和必要的工具分派注册。
- 替换、缩短新报告 system prompt 中原来两工具选择的段落，不新增大段全局提示。语义说明仅位于相关工具描述及回执。未修改前端、SSE、调用预算或模型供应商。

## 真实模型对照

同一组 3 个会话、15 个问句，复用隔离报告中的 300 条已存评论（风险 14、无风险 286）。真实 qwen3.7-plus / DashScope，流式启用。三轮迭代共 45 个真实回合；不修改正式数据库、不重新采集或审核。

| --- | --- | --- |
| 修改前（此前验收） | 3/6 | 两次风险全量缺入口，一次无风险全量多余确认 |

## 必须保留的失败记录

1. A6：“把这条帖子的风险评论都列出来，我要查看每一条原文。”仍选择 preview 连续翻页并在文字中列原文，未创建入口。输入参数符合 schema，并不代表模式符合用户意图。不能将本次修改称为服务端强制保证正确分流。
2. A1 普通查看在工具成功后遭遇供应商 `400 data_inspection_failed`，回合 error、retryable=false。标准输出此前还有一次 `Unknown tool 'read_report'` 告警；现有本轮证据不足以解释这条告警的底层原因，不将整条故障链简单归为本次新工具或纯网络故障。未重放相同拦截 payload，也未修改提示以规避供应商审查。
3. 未指定数量的预览曾在中间迭代显式选 limit=10（而非默认5）；仅参数缺省5不保证模型每次都用5。少量解释仍可能过度概括风险，不能等同于原始审核结果。
4. 新工具没有禁止在有额外分析需求时读取评论，也没有实现“所有评论全量分析”；该能力不在本次范围。
5. 最终逐字核对发现 C2 虽然正确创建列表，回答仍编造 `研判助手://investigation/comment-view`，没有使用真实 ID。删除模型可见 ID 只能防止该 ID 被外泄或拼接，不能保证模型不编造通用链接。真实列表按钮由前端独立读取工具产物提供；该自然语言展示问题尚未消除。
