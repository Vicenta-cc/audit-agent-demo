# 报告账号统计与 TopN（候选改动）

## 目的与范围

对新增统一报告提供后端精确统计，避免 Agent 为人数和 Top5 逐帖翻阅全部评论、自行计算。此次没有追加或修改 system prompt；只修改工具实现、工具自身描述/Schema、概览统计来源、公开工具进度文案及测试。原有评论明细和账号活动查询的权限范围不变。

## 工具契约

`get_report_account_statistics`：

- `report_ref` 可省略，省略时仅统计当前绑定报告。指定其他报告必须使用本会话 `list_authorized_reports` 返回且仍有效的引用。
- `role` 为 `comment_author`（默认）或 `post_author`，按评论数或发帖数排名。
- `top_n` 默认 5，范围 1–20；不接收任意 task ID 或跨会话引用。
- 完整统计来自所选报告的已授权冻结账号活动快照，按稳定身份区分账号，同昵称不合并。
- 返回总评论数、总发帖数、评论者/发布者/去重账号数、未识别身份的评论/帖子数量。活动总数包含未识别身份的活动，但账号总数及排名不包含，`account_counts_complete=false` 明示缺口。
- 排序为活动数降序、稳定身份升序。返回最多 TopN 个具体账号，提供展示位置、竞争排名、同分账号数，以及截止位置遗漏的同分账号数。即使54人并列第五也返回具体第五个账号，不返回54人的完整目录。
- 每个结果含会话安全 `account_ref`，可继续穿透原授权范围的账号活动；当前报告统计不因此扩大范围。

`read_report.account_entry_statistics` 的完整数量字段复用同一统计函数；`displayed_publisher_count`、`displayed_commenter_count` 仍只表示预览入口数量。入口投影不再充当完整账号数量来源。预览卡片本身不在本次重建范围内。
