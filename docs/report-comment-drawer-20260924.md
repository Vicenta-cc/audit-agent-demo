## 产品语义

- 新报告统一使用 `view_post_comments`；普通“看看帖子评论”选择 `display_mode=preview`，默认 all、limit=5；用户明确要求风险评论时才筛选 risk。聊天继续流式回答。
- 明确“全部展示/列出所有评论/全部风险评论”选择 `display_mode=browse_all` 创建可点击的列表入口，不接受 limit/cursor。模型只收到标题、计数和入口已创建状态，不收到全部原文或入口内部 ID；前端通过授权的回合 API 获取入口。
- 点击卡片后 Drawer 每页读取 20 条，滚动接近底部自动加载，也有加载/重试按钮。不要求用户重复说“继续”，不调用模型，不修改对话历史。
- “分析全部评论”不属于该入口的能力。创建列表不等于模型已阅读或分析全量评论。

## 实现边界

仅新增统一审核报告启用新工具；旧报告模式的工具目录不变。现有文字流式回调、SSE、活动进度和模型调用预算没有更改。仅替换统一报告中与全量展示冲突的原有提示，以及调整相应工具说明，没有加入新的大段通用 system prompt。

新报告不再向模型同时暴露 `list_post_comments` 与 `open_post_comments` 两个竞争入口，但旧 handler 保留兼容历史调用。展示模式和风险筛选为新工具必填字段；业务侧校验枚举、分页参数、引用和权限。工具回执携带本步骤交付状态及简短回答指导，不改写用户意图、不按关键词硬分流，不限制后续明确分析请求。模型仍可能选错模式，不能把 schema 校验等同于自然语言意图准确率保证。

列表入口保存在会话工具 ledger 旁的 `.comment-views.sqlite3`，绑定 session、turn、report_version、snapshot_hash、post、risk_filter。同一回合相同选择复用入口；重启后可重新打开。仅保存入口元数据，评论原文仍从已验证的冻结快照读取。

HTTP 请求先经过现有工作台/任务/回合授权，普通会话入口也验证所有者，禁止绕过工作台访问 m3-run 会话。每页再次验证报告快照。前端不接受模型生成的 HTML/URL 作为入口，原文作为 React 文本渲染。

进度“已展示”指 Drawer 列表中成功加载的条数，不声称用户已阅读。失败重试同一 offset 不推进；关闭重开从首批展示，而不是承诺恢复之前的滚动位置。分页位置不参与模型上下文。

当前不包含全量导出、全量分析、Drawer 内选中评论直接追问，也未修改其他错误分类或 Hermes 通用身份。

## 真实 Qwen

使用隔离数据库副本、真实 `qwen3.7-plus` / DashScope，未使用 DMX，未重新采集或重新审核。复用同一篇拥有 300 条评论、14 条风险评论的冻结帖子。

首轮发现“全部风险评论”仍走普通文字工具；随后收窄工具描述并移除“所有评论均使用普通工具”的旧冲突。修正后连续两组、每组 3 轮均按目标路径完成：

1. 先看几条：普通工具，5 条、无卡片。
2. 全部 300 条：创建 all 列表，浏览 15 页共 300 条，位置连续，新增模型调用 0。
3. 全部风险评论：创建 risk 列表，共 14 条，新增模型调用 0。

开启现有公开回答流式开关的第三组，三轮分别记录 13、10、7 个 `answer_delta` 事件，回合均 completed。普通回答耗时 23.04 秒；300 条入口回合 8.38 秒；风险入口回合 10.88 秒（包含测试程序的列表读取）。这些是有限样本通过，不是模型工具选择永不出错的保证。

另外，第二组普通回答曾把 14/300 定性描述成“相当一部分”，该类自然语言概括准确性不属于本次 Drawer 修复，不能以列表计数准确推断所有解释都已正确。
