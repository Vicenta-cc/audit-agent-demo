## 评论与规则

所有逐条评论审核请求将平台 ID 映射为本批 C01、C02 等。模型输出严格匹配当前请求编号，程序还原原 ID 再校验、保存原判断；不按返回顺序或相似字符串猜测。乱序允许，未知、重复、冲突编号拒绝，漏项只补试一次，补试为新的局部映射。失败响应及映射位于 Job/comment_audit_failures。完整评论仍保存真实 ID，融合证据 ID 不变；视频规则 R 编号不变。短编号约束也计入动态 Prompt 总预算。

新独立规则 ID：ruleset.ethnic-content-review.k-trial.v2，bundle：backend/rulesets/bundles/ethnic_k_v2。保留 K1 文件及既有任务冻结快照。K2 评论与汇总均保持 qwen3.7-plus、thinking=true，6000/3000 tokens、120 秒；未调整超时、并发、采集条数或评论覆盖量。

K2 在图像、视频、评论、融合的规则上下文补充相同边界：赞美优秀、自由、强大不自动证明天生人种等级或他族低等；保留部分成员、特定行为者等范围，不能省略“里面这种人”而扩大为全民族。“少数民族”是类别名称，不等于“少数人”。限定对象也不自动豁免明确基于民族身份的个人侮辱、非人化、剥夺权利或暴力。规则非关键词白名单，条件不足不能用 low 兜底。未覆盖其他审核领域的政治指控，不等于证实或认可该指控。

## 运行行为

- 四个帖子循环（流式入库、流式旧格式、采集后补充分析、已有数据补分析）统一保存单帖失败并继续；既有超时/合同补试上限不增加。
- 明确 HTTP 401/402/403、配置不可用，或连续 3 帖 Provider 调用失败，只设置 analysis_stop_requested。成功帖重置连续计数；先前失败不再污染下一帖的 Provider 健康检查。
- 审核线程异常也仅停止审核；采集回调继续入库。爬虫 stop_checker 不读取审核停止标记。采集正常结束后 Job 为 analysis_stopped，Run 为 INTERRUPTED，现有报告页显示采集完成、分析停止。原始待审核内容保留。
- 单帖失败但其余全部处理完：Job 为 completed，分析投影为 partial（部分失败），Run 为 AUDIT_COMPLETED；成功与失败数量分开。此时不自动生成声称全量审核完成的总报告，成功帖详情仍可查看。全量成功仍走原报告流程。
- Job/post_failures 保存帖 ID、失败阶段、异常类型链、HTTP 状态、原因和处置，不写凭据或网络原始错误正文。
- failed 当前仍计入 pending_analysis_count；不能把它当作新增待审核帖数。旧 backfill_analysis 会同时选 queued 和 failed，尚未新增“只补失败”按钮，也未自动重跑旧任务。
