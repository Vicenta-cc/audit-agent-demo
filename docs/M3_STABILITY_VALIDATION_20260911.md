## 修复：评论结果字段身份不明确

真实 Qwen 对合成攻击评论判断出了风险，却把类别写入 `lib`、把规则写入 `t`。严格结果校验拒绝，导致审核失败，未误记为通过。两次重复中共出现四次此类失败。

标准规则编译器现在明确给出风险库 `lib` 与 `rule_id → t` 映射，保留规则命中条件、豁免、等级及严格校验。原 K2 固定提示配置保持不变，已确认任务不回写。历史 golden 文件未改，仅显式验证新增提示段及其派生哈希差异；其他编译输出必须与历史结果相同。示例评论固定提示增加 581 字，预算测试同步记录，硬上限不变。

最终回归 **449 项通过，31 项子测试通过，33.04 秒**；覆盖规则编译、民族 K2 边界、资源生命周期、会话隔离、临时规则、展示采用、创建问答、翻译和评论失败隔离等。生产构建、类型检查与 `git diff --check` 通过。

## 另两项剩余限制

1. 在已有临时规则 Run 的失败会话要求“再建一份”，采用工具拒绝重复草稿；助手把草稿的 `QUEUED` 当成当前 Run 状态，而实际 Run 已 `FAILED`，并建议跨会话复用临时资源。这条恢复流程与解释未验收通过。本次改用新会话读取正式资源完成账号重试，没有伪装为原失败流程已修复。
2. 系统当前按可用账号 ID 排序自动选择，没有通用的自然语言指定账号机制。新账号本次恰为排序首项，且已核对真实绑定；不能据此声称任意说出账号名都会切换成功。
