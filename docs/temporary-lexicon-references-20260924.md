# 临时词库引用采用

## 范围与契约

本次补齐会话编辑稿到调查草案的引用传递，不改词库生成质量策略、模型路由、正式保存授权、规则展示采用门禁或任务启动授权。

- 正式词库继续使用已有 `resource_ref`，读取与保存回执的版本绑定不变。
- 临时词库的生成、打开、读取、修改回执也返回 `resource_ref`。模型可见的 `recall_plan` 仅含 `strategy=resource_ref` 和引用。
- 临时引用绑定用户、会话、编辑稿 ID、版本、内容指纹和来源。hash 不由模型填写。
- 后端解析引用为既有 `temporary_terms` 存储格式，保存完整内容、启停状态、主变体关系及搜索投影。已有草案、执行冻结格式不迁移。
- 修改编辑稿产生新版本及引用；旧版本、跨会话、跨用户引用拒绝。元数据变化也使旧版本失效。
- 保存临时词库不会强迫已有临时引用转换为正式引用。新生成编辑稿原本没有正式来源，保存后再临时使用仍保持原始来源语义；正式采用使用保存回执的新正式引用。
- 创建、更新、采用规则三条草案路径均在创建库写事务内复核临时引用，避免参数解析后发生并发编辑的竞态。
- 同一工具执行身份的持久化成功回执重放不重复创建草案。不同调用身份不属于这一幂等承诺。
- 临时规则继续使用 `presentation_id`，验证已展示的精确版本与后续采用授权；不改成可以绕过展示确认的通用资源引用。

## 模型工具与前端边界

草案工具的模型 schema 不再展示完整 `lexicon_content`，并去掉不可达的词库存储子 schema。旧调用、HTTP 卡片编辑仍接受原结构，兼容已有历史。

前端直接提交结构化编辑内容不经过模型重抄，无须把这条可靠的直接编辑接口改成多轮工具操作。编辑稿卡片通过版本化修改接口提交；随后 Agent 读取编辑稿即可取得新引用。草案 Drawer 仍通过草案 revision 提交完整修改，保留原确认与冻结保护。

只替换既有提示中与新工具契约冲突的采用说明及示例，不追加新的全局提示段落。原 Prompt 的变化在 baseline fixture 中逐行列明原因。

## 自动化验收

2026-09-24：424 项测试、23 个子用例通过（6 条依赖弃用警告）。覆盖：

- 临时、修改后临时、刚保存、正式读取、从正式资源打开并修改的词库，与临时规则、既有正式规则、刚保存规则的 15 种组合。
- 卡片 HTTP 修改 → Agent 读取 → 引用采用，备注引号与反斜线保持不变。
- 长备注、重启后引用、保存后临时引用、元数据变化、跨用户／会话、禁止覆盖临时引用的搜索投影。
- 创建／更新／规则采用三条事务内并发变更拒绝。
- 已采用后编辑源词库不改变草案快照；同一执行身份重放不重复创建。
- 原生成、权限、临时规则展示确认、执行与旧接口兼容回归。

## 真实模型验收和限制

使用统一 DashScope / Qwen 入口、隔离数据库及合成采集账号；只验证创建草案，不进行采集，也不修改当前 3498 会话。

首批两条链路均创建一份草案、零 Run：

1. 色情服务引流内容安全：真实生成词库 → 修改说明 → 真实生成并展示规则 → 临时采用。采用仅携带引用。
2. 招聘诈骗：真实生成词库 → 正式保存 → 真实生成并展示规则 → 读取正式词库并采用。采用仅携带引用。

首批共 31 次 provider 请求。招聘词库首次因超过默认 10 词上限而校验失败，Agent 第二次生成成功；不能把该轮计作“无错误首次成功”。本补丁不改变生成数量策略，也不承诺消除供应商拦截、流中断或生成质量波动。

清理工具说明中的旧全文要求后，最终工作树又独立跑完一次“色情服务引流：生成 → 修改 → 规则展示 → 临时采用”，15 次请求、一份草案、零 Run。词库工具成功后，最终展示阶段出现供应商输出内容检查拦截，Hermes 将其包装为部分流中断并恢复；不能据此归因为普通网络中断。采用工具本身成功，未重抄词库。记录的工具 schema 哈希与当时工作树一致。三条链路总计 46 次请求，均通过真实工具回执与落库数据核对，不只依据最终回答。

首批两条实际搜索词分别为 7 条和 8 条；已核对词库完整内容／实际搜索投影，`max_notes=5`、`max_total_notes=30`、`analyze_limit=30`。本轮账号为隔离测试替身，评论上限沿用测试默认值，不属于每帖 300 评论或真实采集验收。

Hermes 将不可修复的工具 JSON 归入长度截断的错误分类属于外部依赖问题，本补丁没有修改共享 Hermes 安装。引用采用减少相应长 JSON 的输入输出，不等于该诊断问题已修复。

上述验收时未自动提交、推送或重启 3498/8498。部署时必须重启实际服务以加载新的工具 schema；只修改磁盘文件不代表已运行的 Agent 使用了新契约。

## 后续产品决定：默认词数仅作为建议

用户确认默认 5–10 个搜索词不作为硬性失败门槛。生成提示保留原有目标与质量要求，后端移除默认超过 10 个即拒绝的检查；合法内容完整保留，不静默截断，也不为默认词数触发重新生成。上述招聘词库首次超量失败是调整前的历史验收记录。

用户明确指定 `requested_count` 或 `exact_terms` 时仍严格保护数量／原文；空词、重复、结构与字段类型等校验不放宽。此调整不改变采集帖子数量、单任务总量和执行限制。

## 检索执行优先级

确认卡与新任务执行按实际搜索词的风险等级排序：高、中、低、未识别等级，同级保留原顺序。只排序已启用、已选中的搜索词，不加入停用词或标签；重复查询使用启用条目的最高等级。未带结构化风险信息的纯文本词表保持原顺序。

临时词库、正式词库、卡片修改后和正式资源打开编辑后的词库均适用。存储投影、原草案、资源指纹不因排序而重写；确认时冻结实际执行顺序，已确认任务不重新读取风险等级排序。每关键词和任务总采集上限不变；词的风险等级不是采集帖子已经违规的结论。

该调整相关回归 297 项及 23 个子测试通过，包括确认展示与执行顺序一致、同级稳定排序、冻结重放和旧接口兼容。
