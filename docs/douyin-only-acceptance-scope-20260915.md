# 当前采集验收范围：仅抖音

更新时间：2026-09-15

## 决策

当前阶段只验证抖音采集链路的可用性。小红书和快手暂停继续开发、修复和真实验收，避免同时扩展多个平台导致范围失控、问题互相干扰。

本决定只收缩本轮验收范围，不删除已有代码、账号或历史验收数据。后续如恢复小红书或快手，应重新确认范围并单独建立验收清单。

## 本阶段需要验收的抖音能力

1. **账号登录**
   - 用户在管理页内看到并扫描有效二维码。
   - 登录和采集全程不出现独立 Chromium/CloakBrowser 窗口。
   - 登录态能够加密保存，并可被后续任务复用。
   - 登录失效、平台验证和账号冷却状态能够被准确识别。

2. **采集完整性**
   - 内容详情、图片、视频和评论按任务配置保存。
   - 详情或媒体失败时留下明确失败记录，任务不能把缺失内容误报为完整成功。
   - 评论达到上限后停止继续请求。

3. **续抓与去重**
   - 同一任务暂停或中断后，从保存的检查点继续。
   - 已完成内容计入原任务上限，续抓不能超量。
   - 新任务从配置的起始页重新检索，并跳过数据库中已经完整保存的内容。

4. **分页稳定性**
   - 搜索和博主分页不能重复处理同一内容。
   - 连续分页没有新增内容时主动退出，避免任务长期运行。

5. **频率与账号切换**
   - 帖子处理速度、API 请求频率和媒体请求频率含义清楚，不发生多层等待意外叠加。
   - 账号触发验证时，只在存在另一个可用抖音账号时进行一次受控切换。
   - 平台共享限流、网络错误或媒体失败不能被误判为账号失效。

6. **任务状态和页面展示**
   - 暂停、继续、完成和失败状态与实际采集进程一致。
   - “已抓取”只统计主内容，不把评论数量重复计入。
   - 页面展示的执行账号、采集数量和错误原因与后台记录一致。

## 当前已确认的抖音事实

- 隔离验收环境地址为 `http://127.0.0.1:8027`，原 `8017` 环境不用于本轮修改和验收。
- “zc常用账号”已扫码登录并处于可用状态。
- 登录使用后台隐藏的 CloakBrowser，用户侧没有独立浏览器弹窗。
- 已完成一次“风景”关键词 3 条内容的小量真实采集。
- 任务列表的“已抓取”统计已改为只显示主内容数。
- 多召回词续抓已修复：任务初始页与当前召回词检查点分开传递，检查点页只作用于暂停时正在处理的召回词，后续召回词仍从任务初始页开始。
- 多召回词续抓自动验证已通过：模拟“词一”从第 3 页恢复时，“词二”仍从第 0 页请求；应用侧相关测试 15 项通过，爬虫侧相关测试 20 项通过。
- 多召回词真实小量验收已通过：任务 `63279719f69f` 采集“上分、盘口”各 2 条，在“上分”已完成 2 条且检查点切换到“盘口”第 0 页时暂停；恢复命令保持任务起始页为 0，并只把检查点应用到“盘口”。恢复后日志确认跳过已完成的“上分”，只请求“盘口”第 0 页。最终数据库为“上分”2 条、“盘口”2 条，共 4 个不同内容 ID，无超量、无任务内重复、无错误。
- 上述真实续抓进程使用 `--headless true`，账号验收后仍为可用状态，未再次触发平台验证。
- 修复已同步至 8027 隔离环境并完成服务重启；抖音“zc常用账号”仍为可用状态，重启前运行的 20 条真实采集任务保持完成且无错误。

以上事实不等同于整条抖音链路已经最终验收通过。多召回词暂停续抓已经完成真实小量验收；其余仍需按照上一节逐项验证失败记录、评论上限、跨任务去重、分页退出、频率控制和账号切换。

## 暂停处理的平台

### 小红书

二维码登录已经通过隐藏 Chromium 实测，但 CloakBrowser 暂时不能稳定生成可扫码二维码。关键词任务的续抓和跨任务去重已有实现及小量验收。

账号切换审阅发现以下缺口，当前只记录，不修复：

- 现有隔离环境只有一个可用小红书账号，没有实际切换目标。
- 登录态失效会直接使任务失败，不会切换备用账号。
- 博主主页任务未接入自动账号切换。
- 切换后的账号没有写回任务记录，暂停续抓可能再次使用原账号。
- 重新登录不会清除旧冷却状态，前端也没有展示冷却状态。
- 自动切换测试主要覆盖抖音，缺少小红书专项验证。

### 快手

二维码异常和登录问题暂不继续排查，不进入本轮验收。

## 完成标准

只有当本文件列出的抖音能力全部通过自动测试和小量真实采集，并且没有独立浏览器弹窗、超量采集、重复采集或错误成功状态时，才能把当前阶段标记为验收通过。
