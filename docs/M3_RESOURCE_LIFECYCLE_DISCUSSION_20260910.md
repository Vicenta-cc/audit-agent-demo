## 本轮目标

在现有自然语言发起抓取、审核的基础上，让同一个对话可以读取、生成、修改 RuleSet 与 Lexicon；既可以正式保存，也可以不进入正式资源库、仅供本次任务使用。可以修改后台已有资源，并保存更新。保存资源不等于启动任务，启动任务也不要求先保存资源。

## 用户应能完成的操作

| 用户意图 | 预期行为 |
| --- | --- |
| 生成一套规则和词库，只用于这次抓取 | 展示生成内容，沿用任务配置与执行流程，不强制正式入库 |
| 把刚才的规则保存下来，词库不用保存 | 只保存指定规则；当前词库仍可用于任务 |
| 看看后台已有的某个词库或规则 | 读取真实资源，支持获取完整内容，不能用列表摘要代替编辑底稿 |
| 修改已有词库的某些词或已有规则的某条条件 | 基于明确资源与版本生成修改，保留其余字段，展示变更 |
| 把修改保存回原资源／另存一份 | 更新原资源的新版本或创建新资源，返回可再次读取的真实结果 |
| 用已有规则搭配刚生成的词库抓取 | 正式与临时资源可独立组合，不重复生成或强制转存 |
| 只保存资源，暂时不抓取 | 保存完成，不创建或执行抓取任务 |
| 先提出抓取需求，再补足规则与词库 | 保持自然语言任务入口，按需要准备资源，不强制先进入资源管理页面 |

词库完整编辑应覆盖主词、变体、标签及启用状态，但不因可编辑这些字段就自动扩大搜索范围；实际采集词仍应明确展示。规则编辑必须保留条件、例外、适用阶段等结构化内容。

## 建议的内部边界

1. **会话编辑内容**：Qwen 生成或从正式库读取后编辑的内容，有来源和版本，可刷新恢复。这里的“不保存”指不正式入库；为恢复对话及复现任务而保存会话数据与执行快照是必要的。
2. **正式资源**：正式保存产生可复用身份与版本。RuleSet 复用现有草稿、编译和发布能力；Lexicon 需核实并补齐完整编辑版本及并发检查，不能只用采集主词的 hash 代表全部可编辑字段。
3. **任务执行快照**：任务使用用户选定的精确内容。后台后续更新资源或把临时资源正式保存，不回写已确认执行快照，不改变已启动任务。

资源管理与任务编排可共享同一对话入口，但保持独立动作和状态。用户已经清楚表达“修改并保存”时，不机械增加一次保存确认；目标资源不明确或基于旧版本发生冲突时再澄清。沿用当前任务启动边界，不把保存动作解释成执行授权。

## 实施顺序与验收建议

先记录隔离环境中的现有自然语言任务表现，再接通独立资源读取、编辑和保存，最后接入混合资源任务，并做回归。允许改进工具与内部接口，但以用户行为正确和可复现为验收标准。

必须覆盖：

- 正式／临时规则 × 正式／临时词库四种组合都可创建任务。
- 新生成资源可独立保存、仅保存其一，以及任务完成后再保存。
- 已有资源读取、局部编辑、保存后重新读取，字段与版本正确。
- 编辑旧资源但不保存时可用于本次任务，原资源保持原值。
- 后台与对话同时修改时检测冲突；重试保存不会重复建资源或覆盖他人修改。
- 资源更新前已启动的任务继续使用原规则与词表快照。
- 自然语言直接提出抓取需求、补充参数、使用已有资源、采用临时资源和确认执行均正常，无不必要的保存步骤。
- 只读资源、只保存资源的请求不会启动抓取；其他调查与报告能力做必要回归。
- 模型验收检查真实工具调用与实际读写结果，不能只看模型回答“已保存”；执行验收核对最终交给采集器和审核器的内容。

本草案不扩大到文件导入、报告会话重构或强制更换 Draft 生命周期。
