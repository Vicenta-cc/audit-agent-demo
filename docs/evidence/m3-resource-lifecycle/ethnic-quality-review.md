# 民族类规则生成语义检查

实验保留原 `ethnic-authoring-guidance.txt` 全文和现有规则编译器、Hermes 适配器、模型配置。新增指导附加在原创建提示之后，仅对民族关系请求生效。真实验证使用 qwen3.7-plus、thinking 开启；全部在一次性数据库中完成，未启动实际抓取。

## 观察、改进与复验

1. 早期付费生成只列出文字：明确“暂不保存”仍应通过工具创建可编辑的临时资源。后续两类资源均实际落在会话副本中。
2. 首次完整流程生成超出要求的规则条数，并遗漏部分原有覆盖：加入条数检查与独立触发类型检查；允许相邻风险合并。
3. 后续生成偏向只描述对维吾尔族的攻击：加入对维汉双方适用相同攻击边界的说明。专项样例已覆盖两方。
4. 专项样例通婚规则的 `hit_condition` 有独立分支，但 `adjudication_notes` 可能追加强制门槛：明确通婚普遍排斥、血统纯洁/污染、强制干预三个分支独立。最终复验两字段一致。

## 最后一次生成

证据：`qwen-ethnic-final-generation-v2.json`。4 次 provider 请求，46,565 tokens。工具实际创建 6 条规则、3 个主词及各自 1 个变体；没有正式保存、Draft 或 Run。

| 原有能力 | 最终样例检查 |
| --- | --- |

| 民族关联个体攻击 | medium；情侣、红娘、支持者的相关身份/行为/立场关联；不因账号背景把售假等具体批评判为民族攻击 |

## 证据边界

自动断言验证工具结果、条数、持久化与任务边界；上述语义检查是对生成正文的逐项审阅，不是人工标注语料上的准确率测试。全链路四轮验收见 `qwen-resource-paid-acceptance-v3.json`；最后一次仅针对生成质量，没有把它描述为重新执行了整套四轮流程。

模型仍有表述和阶段选择波动：最后样例的维语辱骂规则覆盖视频帧、评论和融合阶段，没有列入独立图片证据阶段；上一专项样例则覆盖了该阶段。现有系统仍允许在确认采用前用自然语言修订规则。没有新增硬编码的规则补全器、民族身份推断或思想倾向评分，也没有证明所有输入的生成质量均稳定。
